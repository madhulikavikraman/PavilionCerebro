# 11. Numeric models: which Hugging Face model reads our meter and sensor numbers

Date: 2026-09-26. Key: `numeric`. Page: `app/site_pages/numeric_ai.py`. Code: `src/cascade/numeric/`.

## Question

Ask 1 (user): "check for a ML model that we can use from hugging face or any similar website that can take input in
numbers and make data processing on top of that for this problem".

Put concretely for Pavilion Cerebro: which openly licensed model can take building time series (meters, circuit
currents, humidity, later pipe flow) and give (a) a day-ahead forecast with an uncertainty band and (b) an anomaly
score, so that a person gets a short review list? And does it beat the simple rule of thumb "same hour last week" on
real data?

## What we found

Research note and verifier corrections: `eval/numeric/research/numeric_hf.json` (copied from the research run,
2026-09-26). Source numbers [n] refer to `eval/numeric/sources.json`.

- **Chosen primary model: `amazon/chronos-2`.** Apache-2.0, not gated. The Hugging Face API reports 119,477,664
  parameters and a 477.9 MB weight file at revision `29ec3766d36d6f73f0696f85560a422f50e8498c` [1][46]. It forecasts
  zero-shot (no training on our data), returns quantiles, and accepts covariates [1][2][4].
- **Second opinion: `amazon/chronos-bolt-small`.** Apache-2.0, 47,718,016 parameters, 190.9 MB, revision
  `772f3d25d38aec6d914c8949dab4462e2d46f5d8` [5][46]. Same `chronos-forecasting` package [3].
- **Live fallback: scikit-learn `HistGradientBoostingRegressor`** plus a split-conformal band. It is already in the
  runtime env, so it needs no new dependency [34].
- **Avoided on licence grounds:** Moirai 2.0 (cc-by-nc-4.0, "research purposes only") [10], TimesFM 3.0 weights
  (non-commercial; TimesFM 2.5 stays Apache-2.0) [9], TabPFN 2.5 to 3.5 weights (non-commercial) [23][24], TiRex
  (NXAI Community License) [27][28].
- **Avoided on install grounds for Python 3.13 on Windows:** MOMENT, Toto, Lag-Llama and uni2ts pin old numpy, torch
  or gluonts versions [11][17][19][21][50].
- **Environment finding:** `chronos-forecasting` pulls `transformers` 5.17, which requires `huggingface-hub<2.0`; the
  runtime env has 2.0.0 [45]. So Chronos runs in the separate `cerebro_ml` env and the site reads its saved outputs.
- **Pretraining overlap (verifier correction):** `Salesforce/GiftEvalPretrain` contains the BDG2 sites Bear, Fox,
  Panther and Rat plus the folders bull, cockatoo and hog [51]. The `amazon/chronos-2` API card metadata lists
  GiftEvalPretrain among its datasets (`eval/numeric/research/hf_api/api_amazon_chronos-2.json`). We therefore
  excluded those seven sites from the test pool. The same card metadata also lists `autogluon/chronos_datasets`,
  which we did not check for BDG2 sites. Chronos-Bolt's training corpus is not named on its card.
- **Datasets.** BDG2 [35][36][48]: real hourly meters. Its LICENSE header says "Attribution-ShareAlike 4.0
  Unported" but the body is the 3.0 Unported legal code, and GitHub reports NOASSERTION; attribution and share-alike
  apply either way. LEAD1.0-small [37][38]: real meter readings with human anomaly labels, no licence stated, so we
  publish aggregate metrics only.

The full catalogue (19 models and tools, with licence, parameter count, weight size, fit and decision) is
`eval/numeric/model_catalogue.json`, generated by `scripts/numeric_catalogue.py` and shown on the page.

## What we built

- `src/cascade/numeric/` (runtime env, no torch):
  - `base.py`: `DataCard` (label must be REAL, SYNTHETIC, SIMULATED or INJECTED), `Provenance` (model id, pinned
    revision, licence, data card, params, git SHA), `ForecastResult` (q10/q50/q90), `AnomalyResult`.
  - `baselines.py`: seasonal naive (lag 168 h), naive (lag 24 h), robust z (residual against the median of the same
    hour over the previous 4 weeks, divided by 1.4826 x the trailing 28-day median absolute residual, shifted one
    hour). The 1.4826 factor is the same `MAD_TO_SD` that `cascade.building.electrical.baseline_anomalies` uses, so a
    threshold K means the same number of standard-deviation equivalents in both. The baselines still differ: the
    building layer uses a fixed hour-of-week median from the first 28 days and a pooled MAD.
  - `tabular.py`: HGB day-ahead forecaster (lags 24/48/72/168/336 h + hour + day of week, so no feature can see the
    forecast day), finite-sample split-conformal band, IsolationForest and supervised HGB anomaly scorers.
  - `datasets.py`: pinned URLs and sha256 for BDG2 and LEAD, `fetch()` with hash check, the office-meter draw,
    and `selection_diagnostics()` (the numbers behind the flat-day rule, written to `backtest_setup.json`).
  - `backtest.py`: rolling-origin frames and scoring (WAPE, MAE, CV(RMSE), NMBE, MASE, pinball, coverage,
    meter-level bootstrap interval, paired bootstrap intervals for WAPE differences, WAPE per site, wins against the
    baseline).
  - `agent.py`: `NumericAgent` with `fit` / `forecast` / `anomaly_score`, backend selection (Chronos only when the
    saved forecast's provenance names the pinned revision, else HGB, else seasonal naive) and `to_observations()`,
    which emits building `Observation`s with `level=None` and the provenance in the text.
- `scripts/numeric_backtest.py`, `numeric_chronos_precompute.py` (cerebro_ml env), `numeric_evaluate.py`,
  `numeric_anomaly_lead.py`, `numeric_catalogue.py`.
- Artifacts: `eval/numeric/*.json` and `*.parquet` (1.3 MB forecasts, 0.3 MB selected meters), one stored model
  bundle `models/numeric/hgb_bdg2.joblib` (7.5 MB, 20 per-meter HGB models, loaded by the page for a live re-run).
- Page `app/site_pages/numeric_ai.py`; tests `tests/test_numeric_*.py` and `tests/test_site_numeric_ai.py`.

Verifier corrections applied: sites in GIFT-Eval Pretrain excluded; eligibility uses only pre-test data; causal
imputation only (forward fill up to 6 h, no backfill, no two-sided interpolation); only hours with a real reading are
scored; the HGB point forecast and band come from one model; model revisions pinned and checked; LEAD shown as
aggregates only; HGB served from stored models, not retrained per click.

## Measured results

### Forecasting (REAL, held out)

Source: `eval/numeric/backtest_bdg2.json` (created by `scripts/numeric_evaluate.py`).

- Test pool: 296 BDG2 office meters; 136 pass the pre-test data rules; 37 remain after excluding the GIFT-Eval sites;
  20 drawn with seed 0 (sites Eagle, Peacock, Robin, Wolf).
- 54 daily origins at 00:00 from 2017-11-01 to 2017-12-24, 24 h ahead. n = 25,916 scored hours (4 target hours had
  no reading). No model was fitted on these weeks: HGB trained before 2017-10-01 and calibrated its band on October
  2017; the "refit" row trained through 2017-10-31. MASE scale: in-sample mean |y(t) - y(t-168)| before 2017-11-01.
- WAPE interval: 95% percentile interval from 1,000 bootstrap resamples of meters, per model. These marginal
  intervals overlap, so they cannot tell two models apart; use the paired differences below.

| Model | WAPE % (95% CI) | MASE | CV(RMSE) % | NMBE % | 80% band coverage | Meters better than baseline |
|---|---|---|---|---|---|---|
| Seasonal naive, lag 168 h (baseline) | 10.12 (7.23 to 14.12) | 1.070 | 18.96 | 0.67 | no band | baseline |
| Naive, lag 24 h | 11.65 (9.49 to 14.59) | 1.111 | 23.92 | 0.60 | no band | 11 / 20 |
| HGB + split-conformal band | 7.00 (5.39 to 9.20) | 0.712 | 12.34 | 0.43 | 0.736 | 19 / 20 |
| HGB refit to 31 Oct (point only) | 6.96 (5.34 to 9.18) | 0.709 | 12.33 | 0.42 | no band | 19 / 20 |
| Chronos-Bolt-small, zero-shot | 6.26 (4.54 to 8.71) | 0.652 | 12.18 | -0.09 | 0.772 | 19 / 20 |
| Chronos-2, zero-shot | 6.19 (4.37 to 8.67) | 0.646 | 12.71 | 0.33 | 0.730 | 19 / 20 |

Mean band width: HGB 20.80 kWh, Chronos-2 16.80 kWh, Chronos-Bolt-small 18.13 kWh. Mean pinball loss over

### Anomaly scoring (REAL human labels, held out by building)

Source: `eval/numeric/anomaly_lead.json` (created by `scripts/numeric_anomaly_lead.py`). LEAD1.0-small, 60 held-out
buildings (seed 0), 140 training buildings. n = 490,417 held-out hourly readings, 10,139 labelled anomalous
(prevalence 0.0207, which is also the PR-AUC of a random scorer). PR-AUC interval: 200 bootstrap resamples of
buildings.

| Scorer | ROC-AUC | PR-AUC (95% CI) | Precision in top 1% | Recall in top 1% |
|---|---|---|---|---|
| Robust z (baseline, no training) | 0.778 | 0.178 (0.131 to 0.319) | 0.309 | 0.150 |
| IsolationForest (unsupervised) | 0.773 | 0.155 (0.115 to 0.218) | 0.322 | 0.156 |
| HGB classifier (supervised, other buildings' labels) | 0.913 | 0.630 (0.552 to 0.697) | 0.884 | 0.428 |

At K = `ANOMALY_MAD_K` = 5 (from `cascade.building.rules`) on the building layer's scale (5 x 1.4826 MAD, as in
`electrical.baseline_anomalies`, but with our trailing baseline rather than its fixed first-28-day baseline), the
robust z flags 20,261 held-out hours (4.13%) with precision 0.238 and recall 0.475 (`at_threshold`).

Correction after review: an earlier version of this note and the page called the operating point at 5 **raw** median
absolute residuals "the building layer's threshold". That is a looser cut (about 3.4 sd equivalents): it flags 33,482
hours (6.83%) with precision 0.167 and recall 0.552. It is kept in `anomaly_lead.json` as `at_threshold_raw_mads`,
labelled as a sensitivity row. Rescaling the score by a constant does not change the ranking metrics: the robust z
ROC-AUC and PR-AUC in the table above are unchanged at three decimals (they moved in the 8th decimal because of the
1e-6 guard term), and the IsolationForest and supervised HGB results are bit-identical to the earlier run.

These values match the research pilot's ROC-AUC and PR-AUC to three decimals: same data, split and seed, re-run by
our own script.

### Indicators on the BDG2 test meters (REAL, no labels)

Robust z at K = 5 on the 1.4826 x MAD scale flags 1,077 of 25,916 scored test hours (4.16%) across the 20 meters
(the share is taken over hours with a score). There are no labels, so this is a review-list size, not an accuracy.
The same K in raw MADs (the earlier version) would flag 2,007 hours (`indicators.sensitivity_raw_mads`). Share of hours outside the 80% band: HGB 0.264, Chronos-2
0.270, Chronos-Bolt-small 0.228 (expected about 0.20 for a calibrated band).

## Conclusions

1. **Use Chronos-2 as the primary numeric model, precomputed offline.** On 20 real office meters it had the lowest
   WAPE (6.19% against 10.12% for last-week's-value; paired difference -3.93 points, 95% interval -5.48 to -2.63) and
   the lowest MASE, and it beat the baseline on 19 of 20 meters. It was not the best model at every site: at Wolf,
   Chronos-Bolt-small and both HGB variants had lower WAPE.
2. **Chronos-Bolt-small is almost as accurate** (WAPE 6.26%), had the best-calibrated band (coverage 0.772) and the
   lowest CV(RMSE). The paired difference Chronos-2 minus Bolt is -0.07 points (95% interval -0.35 to +0.21), so the
   data does not separate them.
3. **The scikit-learn HGB fallback is good enough for live use** (WAPE 7.00%, 19 of 20 meters) with no new
   dependency. Chronos-2 is lower by 0.81 points (paired 95% interval -1.17 to -0.32). Refitting HGB through October
   changed WAPE only from 7.00% to 6.96%.
4. **Every 80% band under-covers** (0.730 to 0.772). Show the bands as a guide and add a recalibration step before
   anyone relies on them.
5. **For anomalies, labels matter more than model choice.** A supervised HGB trained on other buildings' labels
   reached PR-AUC 0.630 against 0.178 for robust z; IsolationForest (0.155) did not beat the no-training baseline.

All outputs stay indicators: `NumericAgent.to_observations()` sets `level=None` and writes "indicator only - human
review; never switches equipment or overrides life-safety systems" into every observation.

## Limits

- 20 office meters from 4 sites, one winter window (Nov to Dec 2017). Other building types and seasons are not
  measured. The bootstrap intervals (marginal and paired) show meter-to-meter spread only, and they resample meters
  independently although the meters cluster in 4 sites, so they are likely too narrow for a new site. The per-site
  table shows the spread between sites.
- **Selection rule change, disclosed.** Numbers in this item are in `eval/numeric/backtest_setup.json`
  `selection_diagnostics` (written by `scripts/numeric_backtest.py`, or `--diagnostics-only`). The draw without the
  flat-day rule (same seed; `draw_without_flat_rule_same_seed`) included two Lamb meters with months of constant
  near-zero readings before the test window (Lamb_office_Gerardo read 0.0018 kWh, minimum and maximum, from April to
  October 2017); the zero-share rule missed them because the value is not exactly zero. Before computing any metric,
  we added a pre-test rule: at most 5% "flat days" (daily max minus min at most 0.1% of the pre-test median) in
  2017-01-01 to 2017-10-31. A 1% limit was tried first; it also removed 13 Robin meters with 5 to 10 flat days each
  (`alternative_limits`). At 5%, the rule removes 7 meters from the non-excluded pool (44 to 37): six Lamb meters (44%
  to 85% flat days) and Robin_office_Shirlene (17%). The final pool is 136 eligible, 37 after the site exclusion.
- **The one meter every model lost on**, Robin_office_Wai, repeats almost exactly week to week in Nov and Dec 2017
  (seasonal-naive MASE 0.010), which suggests gap filling in the source file. We kept it because the rule was fixed
  before scoring.
- Remaining pretraining overlap with the four test sites is not known: the Chronos-2 card also lists
  `autogluon/chronos_datasets`, which was not checked for BDG2 sites. Chronos-Bolt's corpus is not stated.
- The robust-z threshold uses the building layer's K and 1.4826 x MAD scale, but a different baseline, so its flag
  rate on the same series will not equal `electrical.baseline_anomalies`'s.
- No weather or occupancy covariates were used; Chronos-2 supports them but that was not measured.
- LEAD has no stated licence: only aggregates are published. A labelled timeline for one held-out building is written
  to `data/raw/numeric/lead_timeline_local.parquet` (git-ignored) and shown only when `CEREBRO_LOCAL_LEAD=1`.
- The robust-z flags on BDG2 meters have no ground truth. The supervised anomaly model was trained on LEAD and is not
  saved in the repo.
- The derived file `eval/numeric/bdg2_selected.parquet` (20 BDG2 meters, Aug to Dec 2017) carries the BDG2 CC BY-SA
  attribution and share-alike terms.
